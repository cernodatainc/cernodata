# Contributing to Cernodata

Every day, somewhere, a developer runs a PDF parser and hopes. Hopes the tables survive. Hopes the columns stay in order. Hopes the data is clean enough to trust.

We think hope is a terrible strategy. Cernodata exists to replace it with control. And we can’t build it alone.

Welcome. We’re glad you’re here.

This guide explains how to contribute to Cernodata. Following it keeps reviews fast and focused. Your pull request reaches maintainers without the common issues that slow things down.

## Ways to contribute

There is more than one way to help Cernodata grow. Pick the one that fits you best.

- **Pick up an issue:** Our [issue list](https://github.com/cernodatainc/cernodata/issues) is full of tasks waiting for someone like you, from small fixes perfect for a first contribution to larger features. See [Finding something to work on](#finding-something-to-work-on) below to learn how to choose an issue and claim it.

- **Report a bug:** Something broken, or not working the way it should? [Open an issue](https://github.com/cernodatainc/cernodata/issues/new/choose) using the bug report template. The more details you share, such as your Python version, the preset you used and, if possible, a sample document, the faster we can track the problem down. If the bug is a security vulnerability, do not report it publicly. Follow the process described in [SECURITY.md](SECURITY.md) instead.

- **Share an idea:** We are open to ideas of every size, from a new quality check to a completely new direction for the project. Every idea starts in [Discussions](https://github.com/cernodatainc/cernodata/discussions/categories/ideas), where the community can weigh in, refine it and show their support. When an idea is ready to be built, the maintainers turn it into an issue, and from there anyone can pick it up.

## Finding something to work on

The best place to start is the [Issues](https://github.com/cernodatainc/cernodata/issues) tab. If this is your first contribution, look for issues labeled [`good first issue`](https://github.com/cernodatainc/cernodata/labels/good%20first%20issue). They are small, well-defined and a great way to get familiar with the codebase. Once you feel at home, move on to issues labeled [`help wanted`](https://github.com/cernodatainc/cernodata/labels/help%20wanted), which are tasks we would love to see done but cannot get to ourselves right now. Found something you want to take on? Leave a comment on the issue, and a maintainer will assign it to you, so others know it is taken. If there is no progress on an assigned issue for two weeks, it goes back to the pool and becomes available to others. Want to help but would rather not work alone? Use the issue's comment thread to team up with others.
