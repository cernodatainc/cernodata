# Security Policy

The Cernodata team takes security bugs seriously. We appreciate your efforts
to responsibly disclose your findings and will make every effort to
acknowledge your contributions.

## Supported Versions

Only the latest released version of Cernodata receives security fixes.

## Reporting a Vulnerability

If you think you've found a security issue in Cernodata, please **DO NOT**
report it publicly via GitHub Issues, Discussions, Discord or any other
public channel.

### Preferred method: GitHub Private Vulnerability Reporting

1. Go to the [Security tab](https://github.com/cernodatainc/cernodata/security)
   of the Cernodata repository.
2. Click **Report a vulnerability**.
3. Fill out the form with as many details as possible.
4. Submit the report.

### What to include

- A description of the vulnerability and its potential impact
- Steps to reproduce (a sample document, if relevant)
- Cernodata version, Python version and operating system

## What happens next

- We will acknowledge your report within **14 days**.
- We will keep you informed about progress towards a fix and may ask for
  additional details.
- Once a fix is released, we will publish a security advisory and, if you
  wish, credit you for the discovery.

## Security Announcements

Security announcements and remediation steps are published in
[Announcements](https://github.com/cernodatainc/cernodata/discussions/categories/announcements).
